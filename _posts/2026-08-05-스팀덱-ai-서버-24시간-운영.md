# 스팀덱을 AI 서버로 24시간 운영하기

## 들어가며

밸브(Valve)의 스팀덱(Steam Deck)은 휴대용 게임기로 출시되었지만, 그 내부에는 AMD Van Gogh APU(Zen 2 CPU + RDNA 2 iGPU)와 16GB LPDDR5 통합 메모리가 탑재되어 있습니다. 이 하드웨어 구성은 의외로 로컬 LLM(대규모 언어 모델) 추론에 매우 적합합니다. 특히 **통합 메모리 아키텍처** 덕분에 CPU와 GPU가 16GB 메모리를 공유하며, 이는 애플 실리콘(M 시리즈)이 보여준 것과 같은 이점을 제공합니다.

이 글에서는 스팀덱을 24시간 돌아가는 AI 추론 서버로 구축하는 방법을 정리합니다. Ollama와 llama.cpp를 활용한 설치 방법, 모델 선택 가이드, 배터리/전력 관리, 그리고 실사용 팁까지 다룹니다.

---

## 1. 왜 스팀덱인가? — 하드웨어적 이점

### 통합 메모리(Unified Memory) 구조
스팀덱의 가장 큰 강점은 **16GB LPDDR5-5500( LCD) 또는 LPDDR5-6400(OLED) 통합 메모리**입니다. 일반적인 노트북은 시스템 RAM과 VRAM이 분리되어 있어, 8GB VRAM 한계에 부딪히기 쉽습니다. 반면 스팀덱은 최대 12GB를 모델에 할당하고도 OS용 4GB를 남길 수 있습니다.

### 메모리 대역폭
- **LCD 모델**: LPDDR5-5500 쿼드채널 → 약 88 GB/s 이론 대역폭
- **OLED 모델**: LPDDR5-6400 → 약 102 GB/s (약 16% 향상)

토큰 생성은 대역폭 바운드(bandwidth-bound) 작업이므로, 이 수치는 7B 양자화 모델 추론 속도에 직접적인 영향을 줍니다.

### 열적 여유(Thermal Headroom)
- 기본 TDP: 4~15W
- 최대 TDP(휴대 모드): 20W
- 독(Dock) 연결 + 능동 냉각 시: 패키지 전력 45W까지 가능

지속적인 추론 워크로드는 12~18W에서 팬 소음 거의 없이 동작합니다.

### 주의점: ROCm 미지원
AMD는 Van Gogh(RDNA 2 모바일)에서 ROCm을 공식 지원하지 않습니다. 따라서 **GPU 컴퓨트(ROPENCL/HIP) 대신 CPU + Vulkan 컴퓨트**로 추론이 수행됩니다. 하지만 실제 벤치마크에서는 순수 CPU만으로도 Phi-3 Mini 22 tok/s, Llama 3.2 3B 14 tok/s를 기록합니다. 이는 사람 읽기 속도보다 빠릅니다.

## 2. 스팀덱 모델별 선택 가이드

| 구성요소 | LCD 모델 | OLED 모델 |
|---------|----------|-----------|
| CPU | Zen 2, 4코어/8스레드 @ 2.4~3.5 GHz | 동일 |
| GPU | RDNA 2, 8 CU @ 1.0~1.6 GHz | 동일 |
| RAM | 16GB LPDDR5-5500 | 16GB LPDDR5-6400 |
| 저장소 | 64GB eMMC / 256GB / 512GB NVMe | 512GB / 1TB NVMe |
| 배터리 | 40 Wh | 50 Wh |
| TDP 범위 | 4~15W (최대 20W) | 4~15W (최대 20W) |

**추천**: AI 서버 용도라면 **512GB 이상 NVMe 모델** 필수. 7B Q4 모델 하나가 4.4GB, 임베딩 모델까지 모으면 20GB+ 쉽게 넘습니다. 64GB eMMC 모델은 비추천입니다. OLED가 메모리 대역폭과 배터리 용량에서 유리하나, 기존 LCD 소유자라면 업그레이드할 필요까지는 없습니다.

## 3. SteamOS 파일시스템 특이점과 우회 방법

SteamOS 3는 **불변(immutable) Arch Linux** 기반입니다. 루트 파일시스템(`/usr`, `/etc`, `/var` 일부)은 읽기 전용이며, 시스템 업데이트 시 원자적으로 교체됩니다. 따라서 `pacman -S`로 패키지를 설치하면 다음 업데이트 때 사라집니다.

### 권장 우회 방법 3가지

| 방법 | 장점 | 단점 |
|------|------|------|
| **1. `~/.local/bin`에 설치 (권장)** | 홈 파티션은 쓰기 가능, 업데이트 영향 없음 | PATH 설정 필요 |
| **2. Distrobox 컨테이너 사용** | 완전한 개발 환경, 영구 저장소 | 무거움, 초기 설정 복잡 |
| **3. `steamos-readonly disable`** | 가장 자유로움 | 업데이트 시 충돌 가능, 재설정 필요 |

**필자 추천**: Ollama 바이너리는 방법 1로, Python 도구체인(llama.cpp 빌드, 파인튜닝 등)은 방법 2로 병행.

## 4. Ollama 올바르게 설치하기

### Desktop Mode 진입
전원 버튼 → "Switch to Desktop" 선택. Konsole(터미널) 실행.

### 설치 스크립트
```bash
# 1. sudo 비밀번호 설정 (미설정 시)
passwd

# 2. 로컬 바이너리 디렉토리 생성 및 PATH 등록
mkdir -p ~/.local/bin
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
echo 'export OLLAMA_MODELS="$HOME/.ollama/models"' >> ~/.bashrc
source ~/.bashrc

# 3. Ollama 바이너리 직접 다운로드 (systemd 유닛 설치 건너뜀)
curl -L https://ollama.com/download/ollama-linux-amd64 -o ~/.local/bin/ollama
chmod +x ~/.local/bin/ollama

# 4. 버전 확인
ollama --version
```

이 방식이면 SteamOS 업데이트가 와도 `~/.local/bin/ollama`와 `~/.ollama/models`는 건드리지 않습니다.

### 서버 모드 실행 (24시간 운영용)
```bash
# 백그라운드 서버로 실행
ollama serve &

# 또는 systemd 사용자 서비스로 등록 (로그인 후 자동 시작)
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/ollama.service << 'EOF'
[Unit]
Description=Ollama LLM Server
After=network.target

[Service]
Type=simple
ExecStart=%h/.local/bin/ollama serve
Environment=OLLAMA_MODELS=%h/.ollama/models
Environment=OLLAMA_HOST=0.0.0.0:11434
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now ollama
```

`OLLAMA_HOST=0.0.0.0:11434`로 설정하면 같은 네트워크의 다른 기기에서도 API 호출 가능합니다.

## 5. 16GB 통합 메모리에 맞는 모델 선택

| 모델 | 양자화 | 크기 | 예상 속도 (토큰/초) | 용도 |
|------|--------|------|---------------------|------|
| Phi-3 Mini | Q4_K_M | 2.2 GB | ~22 tok/s | 빠른 채팅, 코딩 보조 |
| Llama 3.2 3B | Q4_K_M | 2.0 GB | ~18 tok/s | 범용, 다국어 강함 |
| Mistral 7B | Q4_K_M | 4.4 GB | ~11 tok/s | 추론 능력 우수 |
| Gemma 2 9B | Q4_K_M | 5.5 GB | ~8 tok/s | 최신 지식, 한글 지원 |
| Qwen 2.5 7B | Q4_K_M | 4.4 GB | ~10 tok/s | 코딩/수학 특화 |

**전략**: 주력 모델 1~2개(Q4_K_M) + 임베딩 모델(nomic-embed-text, 0.5GB) 조합이 16GB 내에서 안정적입니다. Q8이나 FP16은 메모리 압박으로 스왑 발생 → 속도 급락.

### 모델 다운로드
```bash
ollama pull phi3:mini
ollama pull llama3.2:3b
ollama pull mistral:7b
ollama pull nomic-embed-text
```

## 7. 24시간 운영을 위한 TDP·배터리·열 관리

### TDP 설정 (전력 제한)
```bash
# 현재 TDP 확인
cat /sys/class/power_supply/BAT0/power_now

# TDP 제한 설정 (예: 15W 고정)
# SteamOS 설정 메뉴: Performance → Power Profile → Custom → 15W
# 또는 콘솔에서:
echo 15000000 | sudo tee /sys/class/hwmon/hwmon*/power1_cap
```

**추천 프로파일**:
- **독 모드(상시 전원)**: 20~25W, 팬 커브 적극적 → 최대 성능
- **배터리 모드**: 10~12W, 팬 저소음 → 배터리 4~5시간 지속

### 배터리 수명 연장 팁
1. **충전 제한 80% 설정**: SteamOS 배터리 설정에서 "최대 충전 80%" 활성화. 상시 독 연결 시 배터리 팽창 방지.
2. **절전 모드 비활성화**: `systemd-inhibit --what=sleep --who=ollama --why="AI server" ollama serve`로 슬립 방지.
3. **화면 끄기**: `xset dpms force off` 또는 SteamOS 빠른 설정에서 화면 밝기 0%.
4. **불필요한 서비스 중지**: `systemctl --user stop steam-updater` 등 게임 관련 백그라운드 서비스 중단.

### 열 관리
- **독 모드**: 수직 스탠드 + 외장 쿨러 권장. 45W 지속 시 표면 온도 50°C+ 도달 가능.
- **휴대 모드**: 15W 이하 유지 시 팬 저소음(35dB 이하), 표면 40°C 내외.

## 8. Open WebUI로 웹 인터페이스 구축

터미널만으로는 불편하므로, ChatGPT 스타일 UI를 Docker로 올립니다.

```bash
# Distrobox 컨테이너 생성 (권장)
distrobox create --name ai-server --image docker.io/library/archlinux:latest
distrobox enter ai-server

# 컨테이너 내부에서 Docker 설치
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker

# Open WebUI 실행
docker run -d \
  --name open-webui \
  --network host \
  -v open-webui:/app/backend/data \
  -e OLLAMA_BASE_URL=http://localhost:11434 \
  --restart unless-stopped \
  ghcr.io/open-webui/open-webui:main
```

호스트의 포트 3000(또는 8080)으로 접속하면 웹 UI 사용 가능. 외부 접근이 필요하면 Tailscale이나 Cloudflare Tunnel 활용.

## 9. 게임 모드와 AI 모드 전환

스팀덱의 강점은 **게임기와 AI 서버를 오갈 수 있다**는 점.

### 게임 모드 진입 시
- `systemctl --user stop ollama`로 서버 중단 (RAM 확보)
- SteamOS가 GPU 메모리 전용 모드로 전환

### AI 모드 복귀 시
- `systemctl --user start ollama`로 재시작
- 모델이 메모리에 로드된 상태라면 첫 요청만 느리고 이후 빠름

**자동화 스크립트 예시** (`~/.local/bin/toggle-ai-server.sh`):
```bash
#!/bin/bash
if systemctl --user is-active ollama >/dev/null; then
    systemctl --user stop ollama
    notify-send "AI Server" "Stopped (Game Mode)"
else
    systemctl --user start ollama
    notify-send "AI Server" "Started (AI Mode)"
fi
```

## 10. 실전 팁과 흔한 함정

| 함정 | 증상 | 해결 |
|------|------|------|
| **`/usr`에 설치함** | 업데이트 후 `ollama` 명령어 사라짐 | `~/.local/bin` 재설치, PATH 확인 |
| **스왑 발생** | 추론 속도 1tok/s 이하로 폭락 | 더 작은 양자화(Q4→Q3) 또는 모델 크기 줄이기 |
| **배터리 팽창** | 상시 충전 3개월 후 뒷판 들뜸 | 80% 충전 제한, 주 1회 완전 방전 사이클 |
| **과열 스로틀링** | 장시간 추론 후 속도 절반으로 저하 | TDP 낮추기, 독 모드에서 쿨러 사용, 팬 커브 조정 |
| **Vulkan 미활성화** | CPU만으로 돌려 성능 20% 손해 | Ollama 설정 또는 환경변수 `OLLAMA_VULKAN=1` |
| **메모리 부족 OOM** | `ollama serve` 크래시, 시스템 프리징 | `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1` 설정 |

### 환경변수 최적화 예시
```bash
# ~/.bashrc 또는 systemd 서비스 Environment에 추가
export OLLAMA_NUM_PARALLEL=1          # 동시 요청 1개만 (메모리 절약)
export OLLAMA_MAX_LOADED_MODELS=1     # 메모리에 모델 1개만 유지
export OLLAMA_FLASH_ATTENTION=1       # Flash Attention 활성화 (속도 향상)
export OLLAMA_VULKAN=1                # Vulkan 컴퓨트 사용
```

## 11. 비용 대비 효과 분석

| 항목 | 스팀덱 (OLED 512GB) | 미니 PC (예: Beelink SER5, 32GB) | 맥 미니 M2 (16GB) |
|------|---------------------|----------------------------------|-------------------|
| 가격(중고/신품) | ~45만원 / ~65만원 | ~35만원 / ~50만원 | ~80만원 / ~130만원 |
| 추론 속도 (7B Q4) | ~11 tok/s | ~15 tok/s (Ryzen 7 5700U) | ~25 tok/s |
| 전력 소모 (유휴/부하) | 5W / 15~20W | 8W / 25W | 6W / 20W |
| 휴대성 | **최고** | 낮음 | 낮음 |
| 게임 겸용 | **가능** | 불가능 | 불가능 |
| 24시간 운영 적합성 | **우수 (배터리=UPS 내장)** | 좋음 (별도 UPS 필요) | 좋음 |

**결론**: 이미 스팀덱을 소유했다면 **추가 비용 0원**으로 24시간 AI 서버 확보. 새로 산다면 미니 PC가 가성비 더 나을 수 있으나, **휴대성+게임+AI 삼위일체**는 스팀덱만 가능.

## 12. 마치며

스팀덱은 "게임기"라는 레이블에 가려진 **휴대용 통합 메모리 AI 워크스테이션**입니다. 16GB LPDDR5, 팬리스 유휴, 내장 배터리(UPS 역할), 독 연결 시 데스크톱급 냉각 — 이 모든 것이 로컬 LLM 서버 운영에 우연히도 완벽하게 들어맞습니다.

핵심 요약:
1. **Ollama는 `~/.local/bin`에 설치**해 SteamOS 업데이트 영향 차단
2. **Q4_K_M 7B 이하 모델**로 16GB 내에서 안정 운영
3. **TDP 10~15W, 충전 80% 제한**으로 24/7 배터리 수명 확보
4. **Vulkan 활성화, Flash Attention**으로 성능 짜내기
5. **게임 모드 ↔ AI 모드 전환 스크립트**로 듀얼 유즈 실현

집에서는 독에 꽂아 24시간 개인 비서로, 외출 시엔 가방에 넣어 오프라인 AI 동반자로. 스템덱 한 대로 두 마리 토끼를 모두 잡을 수 있습니다.
